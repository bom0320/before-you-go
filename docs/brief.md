# Before You Go — Product Brief

## Problem

사용자는 분산된 공식 안내에서 자신의 상황에 맞는 절차를 찾고 대조해야 한다. 전화 연결 등 현재 처리 경로가 막히면 다른 방법을 다시 찾아야 하며 불필요한 전화·방문·재시도가 발생한다. 문제 배경과 사용자 제공 사례, 문제 정의 원문의 보존 상태는 [problem-definition.md](problem-definition.md)에 기록한다.

## Target Users

MVP 대상은 국민연금 임의가입자로서 보험료 변경을 알아보는 본인, 가족을 대신해 절차를 알아보는 사람, 자신의 가입 유형을 모르는 사람이다. 가족을 위한 정보 탐색과 가족의 실제 대리 신청 권한은 구분한다.

## Product Vision

“행정 절차를 바꾸지 않아도, 그 절차를 찾아 헤매는 경험은 바꿀 수 있다.”

사용자가 실제 행동 전에 자신의 상황에 적용되는 절차와 준비 사항을 공식 근거로 확인하도록 돕는다.

공식 자료의 검색·요약에 그치지 않고 사용자 상황과 확인된 요건을 대조한다. 사용자 정보 부족과 공식 근거 부족을 구분하고, 확인된 범위에서 실행 가능한 다음 행동을 제시한다.

## Core Value

- 내 상황에 적용되는 안내와 그 공식 근거를 함께 확인한다.
- 아직 답하지 않은 질문과 기관에 확인해야 할 사항을 구분한다.
- 현재 경로가 막히면 공식적으로 확인된 대체 경로와 적용 조건을 확인하고 다음 행동을 선택한다.

Verified, Not Guessed / Ask Before Assuming / Actionable Guidance / Clear Responsibility / Minimal MVP Scope를 판단 기준으로 삼는다.

## MVP Scope

MVP는 국민연금 **임의가입자의 보험료 변경 절차 안내와 사전 점검**으로 제한한다. 입력 검증, 상황별 질문, 요건·준비 사항 대조, 신청 경로와 적용 조건, 전화 연결 실패 시 검증된 대체 경로, 출처 및 다음 행동을 제공하는 것이 목표다. 실제 업무 규칙은 공식 자료 확인 후 구현한다.

현재 `/mcp` 도구 한 개에 기존 test 분기와 업무 점검 분기를 구현했다. Research Agent가 공식 자료를 검색하고 서버가 직접 읽은 원문으로 경로·진입점·확인할 조건을 조사한다. 현재 입력만으로 개인의 신분·인증·대리 권한 전체를 독립 검증할 수 없어 ready·not_ready·use_channel은 보류한다. 키·검색 API 장애는 도구 오류로 구분한다. 실행 방법은 [README](../README.md)를 따른다.

## Non-Goals

실제 신청 제출·본인 인증·결제·정부기관 계정 연동, 신청 승인이나 변경 완료 보장, 모든 국민연금 가입 유형 지원은 제외한다. 프론트엔드·DB·인증 시스템 및 에이전트 조직 구조도 이번 설계 범위에 넣지 않는다.

## User Scenarios

| 상황 | 목표 동작 | 피해야 할 판단 |
| --- | --- | --- |
| 임의가입자 본인이 변경 의향을 밝힘 | 변경 목표 등 필요한 상황을 확인하고 검증된 요건에 대조 | 통신 성공을 준비 완료로 표시 |
| 전화 연결이 어려움 | 전화 경로 자체의 적법성과 현재 어려움을 구분하고 조건이 확인된 대체 경로 안내 | 온라인·모바일·방문이 가능하다고 추측 |
| 가족이 대신 변경하려 함 | 대리 신청 의향을 분리하고 공식 자료에서 허용 범위·요건 확인 | 가족이면 신청 가능하다고 단정 |
| 가입 유형을 모름 | 가입 유형 확인 질문과 확인 경로 제시 | 임의가입자로 간주 |
| 다른 가입 유형임 | 현재 지원 범위를 설명하고 공식 확인 필요 사항 표시 | 임의가입자 규칙 재사용 |

## Success Criteria

- 본인·가족·가입 유형 미확인 시나리오에서 정보 부족, 근거 부족, 지원 범위를 구분한다.
- 경로의 존재, 사용자별 조건 충족, 사용자가 보고한 이용 어려움을 독립적으로 표현한다. 대안이 미확인이면 확인 필요로 남긴다.
- 모든 행정적 판단·준비 사항·접수 안내가 검증된 공식 출처의 구체적 사실에 연결된다.
- 미확인 대리 신청 요건이나 다른 가입 유형에 추측 규칙을 적용하지 않는다.
- 응답에서 사용자가 다음 질문 또는 다음 행동과 그 이유를 알 수 있다.
- 구현 시 타입 검사, 업무 분기 테스트, MCP tools/list·tools/call 검증을 통과한다.

현재 통신 테스트 통과는 업무 MVP 완성을 의미하지 않는다. 실제 불필요한 방문 감소 효과는 추후 사용자 검증 대상이다.
