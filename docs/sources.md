# 공식 행정 정보 관리

## 목적과 현재 상태

국민연금공단 공식 자료에서 확인한 사실만 업무 규칙으로 사용하기 위한 기록 기준이다. **이번 문서 작업에서는 개별 행정 자료를 조회·검증하지 않았다. 등록된 verified 사실은 없다.** 아래 항목은 조사 목록이며 신청 가능 여부·서류·채널을 확정하지 않는다.

## 출처 선택과 검증 기준

- 국민연금공단이 제공한 공식 업무 안내·FAQ·서식·공고 등 원문을 우선한다. 검색 결과 요약, 블로그, 모델 기억은 근거로 등록하지 않는다.
- 공식 URL 여부뿐 아니라 해당 페이지가 보험료 변경, 적용 가입 유형, 본인·대리 신청 중 어느 범위를 설명하는지 확인한다.
- 공식 도메인이라는 이유만으로 개별 주장을 verified로 바꾸지 않는다. 직접 URL, 제목, 관련 절·항목 또는 PDF 페이지와 확인한 사실을 기록한다.
- 안내가 참조하는 법령이 필요하면 공식 법령 원문도 별도 출처로 확인한다. 적용 시점·우선 관계를 추측하지 않는다.
- 사실별로 기록을 나눈다. 한 페이지에서 본인 절차를 확인했더라도 대리 신청 조건까지 검증한 것으로 취급하지 않는다.
- 자료끼리 충돌하거나 개정·폐지·링크 단절이 확인되면 관련 사실을 pending으로 변경하고 이유를 남긴다. 새 구현·데모 전에 적용 근거의 최신성과 범위를 재확인한다.

## 기록 필드

| 필드 | 작성 기준 |
| --- | --- |
| 사실 ID | 예: `NPS-001`. 결과 evidenceIds 및 향후 코드·테스트에서 참조할 안정적인 ID |
| 기관명 | 원문 발행 기관 |
| 공식 URL | 확인한 직접 URL. 미확인이면 `미확인`; URL을 추측하지 않음 |
| 자료 제목 / 위치 | 제목과 절·항목 또는 PDF 페이지 |
| 대상 업무 | 해당 사실이 설명하는 업무 |
| 적용 가입 유형 | 원문에서 확인된 범위. 미확인은 그대로 표시 |
| 확인된 사실 | 원문이 뒷받침하는 최소 단위의 요약. 없으면 `없음` |
| 예외 및 제약 | 원문의 예외, 신청 주체·채널·시점 제한. 모르면 `미확인` |
| 검증 날짜 | 원문을 실제 확인한 날짜 YYYY-MM-DD. 미검증은 `—` |
| 검증 상태 | `pending` 또는 `verified` |
| 사실 분류 | requirement / applicant / channel_existence / channel_condition / application_page / preparation / subscriber_lookup |
| 경로 / 연결 ID | 해당 시 phone·online·mobile·visit와 관련 사실 ID. 경로 존재·조건·페이지 사실을 구분하여 연결 |
| 검증 메모 | 확인자, 원문 게시·개정·시행일(표시된 경우), 충돌·보류 이유, 다음 확인 사항 |

`pending`은 미조회, 범위 불명, 충돌, 최신성 재확인 필요를 포함한다. 이유를 메모에 구분한다. `verified`는 특정 사실이 특정 범위에서 확인되었다는 뜻이며 모든 사용자에 대한 적용 보장이 아니다. 검증 날짜와 문서 시행일은 다르다.

NPS-001은 변경 요건, NPS-003은 신청 주체·대리 조건, NPS-004는 가입 유형 확인 방법의 조사 기준으로 계속 사용한다. NPS-002의 본인 절차와 신규 경로 항목은 서로 연결하되 같은 사실을 중복 확정하지 않는다.

NPS-009~011처럼 여러 경로·주장을 포괄하는 pending 항목은 조사 묶음이다. 검증 시 `NPS-009-01`처럼 고유 하위 사실 ID를 부여하고 한 사실·한 적용 범위로 분리한다. 일부만 확인했다고 상위 묶음 전체를 verified로 올리지 않는다. 하위 기록은 위 기록 필드를 모두 갖추고 원래 ID를 검증 메모에 연결한다. 같은 사실이 여러 자료에서 확인되면 한 사실 ID 아래 근거를 연결하고, 상충하면 다음 규칙으로 보류한다.

### 충돌과 사용자 진술의 취급

공식 자료가 충돌하면 양쪽의 직접 URL·제목·관련 원문 위치·게시/시행일·적용 가입 유형·신청 주체·경로와 서로 다른 주장을 검증 메모에 병기한다. 해결 근거를 확인하기 전 pending을 유지하고 코드와 MCP 응답에서 확정 근거로 사용하지 않는다. 이번 작업에서 실제 확인한 충돌 사례는 없다.

사용자의 “전화 연결 실패”는 요청 상황이며 공식 사실 ID나 법적 불가 근거로 저장하지 않는다. 경로가 공식적으로 존재한다는 사실과 그 사용자가 조건을 충족한다는 판단은 별개다. 신청 URL을 찾았다는 사실만으로 해당 사용자에게 이용 가능하다고 안내하지 않는다.

조사 대상의 이름은 사실 확인 결과가 아니다. 특히 가족 관계만으로 대리 권한이 성립한다고 해석하지 않는다. 다른 가입 유형은 이 표의 조사 대상을 임의로 확대하지 않고 범위 변경 시 추가한다.

## 규칙으로 전환하는 순서

1. 공식 원문을 읽고 직접 URL과 자료 위치를 기록한다.
2. 확인된 사실, 적용 범위, 예외와 날짜를 채운다. 불명확한 부분은 pending으로 분리한다.
3. verified 사실에 한해 업무 규칙·테스트 사례와 연결한다. 해석이 개입하면 원문 사실과 해석을 구분하고 미해결 해석을 확정 규칙으로 쓰지 않는다.
4. 도구 응답에는 적용한 verified 사실만 evidence로 제공한다. pending ID를 확정 근거처럼 인용하지 않는다.
5. 근거 변경 시 관련 규칙·테스트·문서를 함께 검토한다. 검증이 끝날 때까지 관련 판단은 needs_verification으로 남긴다.
